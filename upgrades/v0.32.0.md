## What changed

- **`skills/process/evals/`** — 3 evals: new-contract shape (fixed numbered
  Rules / Output schema / Persistence with an idempotency key / Judgment
  latitude / Guardrails / Progress reporting naming `.claude/flywheel/runs/` /
  Improvement log empty at creation), DATA.md bootstrap when the target repo
  has no data strategy, and deliberate maturation of an existing contract
  (version bump + dated Improvement-log entry + original rules preserved).
- **`skills/run/evals/`** — 3 evals over the fixture `plate-audit` contract:
  happy-path persist (exact deterministic fields land in the datastore per
  DATA.md and the write is staged; telemetry report rendered under
  `.claude/flywheel/runs/plate-audit/`), idempotent upsert (a re-audit updates
  the seeded row instead of duplicating it), and the invalid-input guardrail
  (a rejection is recorded, no fabricated audit row).
- **Graders are committed scripts**: `evals/check.sh <id> <workdir>` prints
  PASS/FAIL per expectation. Verified before the real runs — red on an
  untouched fixture, green on correct output, and red on adversarial output
  (a fabricated row; a silently rewritten rule). `FW_EVAL_DATE` pins the run's
  date so regrading a workdir on a later day still grades the same.
- **Fixture** (`demo-repo` / `target-repo`) versioned next to the evals, its
  setup recipe captured as a `type=fixture` learning; its Progress reporting
  section tracks v0.30.0's two-tier telemetry.
- **Benchmark evidence** under
  `skills/{process,run}/evals/benchmarks/2026-07-29/`: 1 real iteration with
  fresh-context subagents, with-skill only (the gate needs regression
  detection, not the value baseline) — 6/6 evals, 49/49 assertions, ~237k
  subagent tokens.
- **README**: the pillar-1 and pillar-2 eval sections are merged into one
  "Skill evals" runbook covering all four skills.
- **Spec**: `.claude/flywheel/specs/p22-evals-pillar2.md` with a
  machine-checkable success metric; cycle telemetry under
  `.claude/flywheel/runs/p22-evals-pillar2/`.
