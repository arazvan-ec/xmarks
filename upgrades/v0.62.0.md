## What changed

`scripts/gate.sh` wrote its cost cache to
`$PROJECT_DIR/.claude/flywheel/.gate-state` — **inside the repo it watches**. An
untracked file that reappears the moment it is deleted makes every `git status`
report a change that corresponds to no change, and the Stop hook's own advice
("commit your work") ends up fighting a file that must never be committed: it is
one machine's cache, not repo content. Every consuming repo had to add a
`.gitignore` entry for a file that was not theirs.

- **The cache now lives beside `trusted-gates`**, under
  `${XDG_STATE_HOME:-~/.local/state}/flywheel/gate-state/`.
- **One file per project**, keyed by a hash of its absolute path. This is the
  part a naive fix gets wrong: a single shared file would make each repo evict
  the previous one's entry, and the cache would never hit. `sha256sum`, falling
  back to `shasum -a 256`, then to a flattened path.
- **The opt-in check moved after the `STATE_DIR` validation**, deliberately:
  `STATE` is derived from `STATE_DIR`, so using it before that directory is
  validated would inherit its threat.

Two new cases in `scripts/test-gate.sh`, both red before the change: the cache
leaves nothing inside the repo, and two projects do not share one file.

## What it costs you

**A stale `.claude/flywheel/.gate-state` is left behind** in any repo that ran an
earlier version. Nothing reads it any more; delete it, and remove the
`.gitignore` entry that was guarding it — flywheel's own `.gitignore` drops that
line in this release.

The cache starts empty at the new location, so the first `Stop` after upgrading
recomputes instead of hitting the cache. One slower run, once.
