## What changed

- **`bytes_in`, a fourth cost proxy** — bytes of file and command content a
  transition pulled into context, beside P23's three. It is a **floor**, not a
  total: charged once per read, nothing for the conversation, nothing for
  content that re-enters context. Labelled as a proxy wherever it surfaces, the
  same rule P23 set for the other three.
- **Per-field accounting in `scripts/run-cost.sh`** — coverage is now counted
  per field rather than per line. A field no transition carries reports
  `UNMEASURED` and is left out of the totals; partial coverage prints with its
  count (`PARTIAL (1 of 2 transitions carry it)`); a two-run delta refuses any
  field either side never recorded, naming which side is blind.
- **Why that shape.** Every run written before this release has a `cost` object
  with three fields and no `bytes_in`. Folding that absence into the totals as 0
  would make each old baseline look as though it read nothing, and hand the next
  optimization a fabricated win. This is P23's `unmeasured` rule — which covered
  a missing cost object — applied one level down, to a missing field inside one.
- **No `tokens` field, unchanged** — a session cannot observe its own token
  usage, so recording one would put unverifiable evidence in the ledger (P18).
  `run-cost.sh` still warns when it finds the key.
- The four documented schema sites and the README name the new field.
