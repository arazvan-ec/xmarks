## What changed

- **`skills/run/SKILL.md` step 4 — the maturation is committed.** It ended with
  *"Stage the contract if you changed it."* It now commits:
  `git commit -m "<what changed>" -- .claude/flywheel/processes/<slug>.md`,
  pathspec-scoped to the contract **alone** — never the datastore row, never the
  telemetry. Fails open: a commit that cannot be made is reported once and the
  persisted result is still reported.

- **It does not push**, deliberately. Pushing needs a branch decision a run has
  no business making alone, and the consequence is stated in the skill rather
  than hidden: a committed-but-unpushed improvement is still lost when an
  ephemeral clone is reclaimed. This narrows the loss; it does not close it.

- **`skills/run/SKILL.md` step 1 — a bare invocation lists.** No slug now prints
  the repo's contracts (name + the first `## Purpose` sentence, never the
  persistence line) and stops; only with none does it point at
  `/flywheel:process`. Deferred from v0.49.0 for want of 140 B.

- **`scripts/invocation-budget.txt` — `run body` 4,800 → 5,800.**

## Why this was losing work

An ephemeral session — the documented Claude Code web path, and every agent run
— discards a staged change when it ends. The row the run wrote to the datastore
survives, because DATA.md decides how results persist. So the process kept the
answer and forgot what it learned producing it.

Observed three times on 2026-09-14 before the change, each executor staging and
stopping *because the skill said to*: two during the v0.49.0 gate, one in this
release's own red run.

## The commit carries the contract alone

The run also wrote a datastore row and telemetry. Those belong to the repo's
conventions — for a git-native store, "staged" may *be* the declared proof of a
landed write — so sweeping them into a commit labelled "mature the contract"
would override DATA.md with a habit. The contract is the plugin's artifact; the
row is the repo's. The eval asserts it: the commit touching the contract must
carry exactly one file.

## Why the ceiling moved, and how the number was chosen

`run`'s body is 5,248 B of nothing but rules. v0.49.0 already moved out every
byte of argument and every catalogue, so the order this repo records — argument
to an uncited `docs/research/` note, then catalogue to `references/`, then the
number — genuinely reaches the number here.

The ceiling was set **last, from the measured body**, not first to fit the diff:
5,248 + the ~500 B a feature costs, which is the figure v0.49.0 measured across
three ceiling breaches rather than the ~300 B guessed when the gate was written.
The default 4,800 was never sized for a skill carrying a five-step contract
runtime.

## Eval gate

- `run` eval 1 — **7/7**, including three new assertions read from **git**
  rather than the working tree (HEAD's contract carries the dated Improvement
  log entry; nothing left staged; the commit carries one file). Red→green proven
  on real runs of the same skill: the pre-change run matured and staged (3 FAIL),
  the post-change run matured and committed (7/7).
- `run` eval 4 — **7/7**, re-run because step 1 changed again. The probe still
  refuses before Rule 1 and still leaves the fallback target byte-intact.

## What this does not fix

**A run blocked by a defect in its own contract has no defined behaviour**, and
this release does not add one. Building the eval for this feature surfaced it:
given a contract whose Output schema contradicted its own Rules, two competent
executors split — one proceeded with the true value and matured the contract,
the other refused to emit a non-conforming output *and* refused to mature,
holding that a schema change with a version bump is not a blocked run's call.
The second reading is correct on the skill as written. The silence is the gap,
and it is slice 3's, because it is a new requirement rather than a bug in this
one.
