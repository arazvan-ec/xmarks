summary: Extends v0.27.0's approval-coherence from writes to commands (P21). A new allow-only PreToolUse hook on Bash pre-approves the single plain git commands that advance the loop's own branch after the plan approval — add, commit, stash push/pop/list, and a force-free push of the current non-default branch to origin, checked live against the repo. Chained commands, global git flags, force pushes and every other verb keep the normal prompt. Spec and process sign-offs now offer (never impose) to write the repo-specific metric/datastore permission rules into project settings, and /flywheel:sync flags pre-existing sign-offs that lack them. Marketplace installs pick it up on /plugin update + reload; vendored repos on re-vendor.

## What changed

- **New `scripts/bash-allow.sh`**, wired as a `PreToolUse` hook on `Bash`
  (`hooks/hooks.json`): after the plan approval, the loop's own git
  advancement no longer re-prompts. Grants exactly four things, on ONE plain
  command at a time: `git add`, `git commit`, `git stash` (bare/`push`/`pop`/
  `list`), and `git push [-u] origin <branch>` only when force-free and
  `<branch>` **is the current branch and not the default one** — resolved
  live via `git branch --show-current` and `origin/HEAD`, which is what a
  static permission rule cannot express.
- **Allow-only, fail-open, and conservative by construction**: any shell
  metacharacter outside single quotes — chaining (`&&`, `;`), pipes,
  redirects, `$(…)`/backticks (even inside double quotes), globs, escapes,
  newlines — disqualifies the whole command, so `git commit -m "x" && rm -rf /`
  never rides the commit grant while `git commit -m "fix: A & B"` (quoted)
  sails through. Global git flags (`-C`, `-c`, `--git-dir`, `--work-tree`)
  disqualify too: the verb must be git's first argument. A cwd outside the
  project, a foreign remote, a refspec (`src:dst`), `--force*`/`--delete`/
  `--mirror`, `stash drop/clear`, and every other git verb fall through to
  the ordinary prompt. Docs-guaranteed: a hook "allow" never overrides an
  owner's explicit deny/ask rule.
- **Gate-time consent for repo-specific commands** (the part the plugin
  cannot know): `/flywheel:spec` — when the Success metric fixes a command —
  and `/flywheel:process` — when DATA.md fixes the write path — now **offer**,
  in the same message as the sign-off, to append the matching narrow rule
  (e.g. `Bash(npm test*)`, `Bash(psql*)`) to the project's
  `.claude/settings.json` `permissions.allow`, committed with the spec/
  contract. One question, once per repo, at the exact moment the owner is
  approving that command; never written unasked. `/flywheel:sync` gains a
  third drift class flagging signed pre-P21 specs/contracts that lack their
  rule.
- **Turn-scoping documented where it bites**: `work` and `ship` now say to
  prefer single commands over `&&` chains — grants and rules match
  subcommand-by-subcommand, so chains re-prompt where plain commands pass.
- **Vendored installs covered**: `install-vendored.sh` vendors the script
  into `.claude/flywheel/bin/` and merges the `PreToolUse`/`Bash` entry into
  the target's `settings.json`; `--uninstall` removes both.
- **Tests**: new `scripts/test-bash-allow.sh` (40 assertions: the four grant
  classes; chaining/substitution/redirect/quote escapes; global-flag,
  force-push, default-branch, foreign-remote, refspec and foreign-cwd
  refusals; fail-open on bad input or missing python3), wired into CI;
  `test-install-vendored.sh` asserts the vendored hook installs, merges
  once, runs, and uninstalls.
- **Docs**: README's permission section now covers both hooks and the
  gate-time consent flow; P21 recorded in the proposals backlog + decision
  log.
