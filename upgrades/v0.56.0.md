## What changed

P40a added `cost.bytes_in` a day after P23's three proxies. Counted across every
telemetry file in the repo before this release: **18 lines, none carrying
`bytes_in`, none carrying `tool_calls`.** The instrument had never received a
data point.

The cause was structural. Conforming lines were written at the end of a cycle
and derived from git, where bytes written and elapsed time survive and read
volume does not. `work` asked a session to "sum what you actually read" — a
running total it was never given anywhere to keep — so every honest session left
the field out, and `run-cost.sh` correctly reported UNMEASURED forever.

- **`scripts/read-meter.sh`** sits on `PostToolUse` for every tool and appends
  one line per call: the tool, a timestamp, and the bytes of `tool_response`
  that entered context. `--since <ts>` totals it for a transition line.
- **`work` reads the two fields instead of recalling them.** The rule now cites
  the meter with the previous transition's `ts` as the cut.
- **A write tool's echo counts as a call, never as bytes.** Probed rather than
  assumed: an `Edit` response carries `originalFile` — the whole file before the
  change — while what reaches context is a one-line confirmation. Charging it
  would let edit echoes dominate `bytes_in`.
- **An observed zero is not UNMEASURED.** A meter that ran and read nothing
  since the cut reports `0`; no meter at all reports UNMEASURED and tells the
  caller to omit both fields. Conflating the two is the P40a fabrication one
  level down.
- **Registered in all three wirings** — `hooks/hooks.json`,
  `install-vendored.sh`, and this repo's own settings — the directions
  `check-hook-parity.sh` asserts, each seen red before being fixed.

State lives in the system temp dir keyed by session, never in the project.
Fail-open throughout: a meter must never cost a read.

Also fixed: `test-check-hook-parity.sh` guarded "this test never touches the real
repo" with `git diff --quiet`, which answers whether the worktree is dirty and so
went red on anyone mid-edit of the files it guards. It compares hashes now.

Release gate: `work` eval 1 graded **7/7 before the version was bumped**, and the
executor's transition line carried `bytes_in=13963` and `tool_calls=15` read from
the meter — the first values either field has held in the repo's history.
