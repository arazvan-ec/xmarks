## What changed

- **Transition line gains a `cost` object** in `skills/{work,loop,run,process}/SKILL.md`:
  `bytes_out` (bytes this transition wrote), `tool_calls`, `elapsed_s` (seconds
  since the previous line). All three are observable from inside a session. If a
  field cannot be computed, the whole `cost` object is omitted rather than
  guessed.
- **No `tokens` field, and the ban is enforced rather than documented.** A
  session cannot observe its own token usage; a guessed number is exactly the
  unverifiable evidence P18 exists to keep out of the ledger.
  `scripts/run-cost.sh` warns when it finds a `tokens` key.
- **Proxy labelling is mandatory** in both surfaces — the report's cost block and
  the script's header — so `bytes_out` is never later misread as a token count.
- **`scripts/run-cost.sh <run.jsonl> [baseline.jsonl]`** totals a run and, given
  a baseline, prints the per-field delta with sign and percentage. A zero
  baseline prints `n/a`, not a bogus percentage. Paired test:
  `scripts/test-run-cost.sh`, 8 scenarios, developed red→green.
- **Unmeasured is never zero.** Transitions with no `cost` object — every run
  from v0.16.0 to v0.32.0 — are reported as UNMEASURED and the two-run delta
  carries an incompleteness note. Counting them as 0 would make old runs look
  free and flatter every comparison.

## Release gate (2026-07-30)

Ran with fresh-context subagents; evidence under
`skills/{work,process,run}/evals/benchmarks/2026-07-30/`:

| suite | evals | assertions |
| --- | --- | --- |
| `work` | 2/2 | 8/8 |
| `process` | 3/3 | 39/39 |
| `run` | 3/3 | 10/10 |

**The `run` suite is what actually verifies this release**: all three runs
emitted a `cost` object on every transition of their real telemetry (14/14,
14/14, 15/16), none emitted a `tokens` key, and `run-cost.sh` produced a real
two-run delta (−1,143 bytes, −57.1%). The `work` suite does **not** exercise the
change — `work`'s telemetry only applies inside a `/flywheel:loop` cycle and the
eval runs it standalone — so its value here is regression detection only. That
limit is recorded in its benchmark rather than left implied.

## Known follow-ups

- One executor omitted `cost` from its closing `run_end` line. The tool reported
  it honestly as unmeasured, but the schema should state explicitly whether
  `run_end` carries its own cost or the run totals.
- **Whether these proxies track real token spend is still unverified.** That
  needs two comparable real cycles, and it is the first thing to do now that the
  fields exist — otherwise this release repeats, one level up, the unverifiable
  cost claim it was written to fix.
