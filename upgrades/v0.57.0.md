## What changed

P44 gave `bytes_in` and `tool_calls` a source. `elapsed_s` still came from
commit-time deltas — and a delta needs a previous commit, which the **first**
transition of a cycle does not have. Counted before this release: p42 4/5, p43
3/4, p44 3/4, every run missing exactly its opening line. The same method
measures nothing at all where the workdir is not a git repo, as `work`'s own
eval fixture is not.

- **`read-meter.sh --since <ts>` also prints `elapsed_s`** — `now - cut`, the
  transition's wall clock. Exact when the line is written at the transition,
  which the duty already requires.
- **`--since first`** cuts at the earliest call the session recorded: the only
  start a cycle's opening transition can observe. If the session did other work
  before the cycle, that cut predates it — the rule says to pass the explicit
  cycle-start ts instead, and the release gate's executor hit exactly that case
  and handled it correctly.
- **A malformed cut now fails loudly.** It threw a traceback, printed no fields
  and still exited 0, so a caller could read silence as data. It exits 2 with a
  usable message, and the reader propagates python's status instead of a
  hardcoded `exit 0`.

No schema change: existing counter files and existing telemetry stay valid, and
`elapsed_s` keeps meaning wall clock rather than tool time. A busy-time proxy
from the payload's `duration_ms` is deliberately **not** added — it is a
different quantity and nothing reads it.

Release gate: `work` eval 1 graded **7/7 before the bump**, and its transition
line carried `elapsed_s=125` from the meter in a workdir where the old method
had nothing to measure.
