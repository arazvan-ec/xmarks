## What changed

- **`skills/verify/evals/check.sh`** and **`skills/work/evals/check.sh`** (new),
  on pillar 2's contract: `check.sh <eval-id> <workdir>`, one `PASS:`/`FAIL:`
  line per expectation, exit 0 only if all pass, exit 2 on an unknown id. One
  runbook step now covers all four skills.
- **Each grader mechanizes exactly the `expectations` already in its
  `evals.json`** — no assertion invented, none dropped. P26 builds the
  instrument; it does not redefine what is measured, so the pending `verify`
  iteration measures the skill rather than a moved goalpost. `evals.json` is
  untouched in this release and the committed benchmarks stay comparable.
- **`work` is graded from artifacts, never from the transcript**: `.check-log`'s
  first entry `RESULT=FAIL` with `IMPL_SHA` equal to `baseline-sha`, last entry
  `RESULT=PASS`, plus a **behaviour probe** (`apply_discount` arithmetic and its
  `0..100` bounds; `add_item` rejecting `qty <= 0` without breaking the happy
  path) and an independent suite re-run. The re-run uses `python3 -m unittest`
  directly, which does not append to `.check-log` — grading must not mutate the
  log it grades, and the test asserts the log is byte-identical afterwards.
- **`verify` is graded from the two saved artifacts**: the verdict regex on the
  last non-empty line of `report.md`, no `VERDICT: PASS` anywhere in a
  planted-bug report, the cited evidence, and the real CLI in `transcript.md`
  for eval 2. `FW_EVAL_REPORT` / `FW_EVAL_TRANSCRIPT` override the paths. **A
  missing artifact is a `FAIL:` naming the path** — a grader that passes on
  absence is worse than no grader, because it reads as evidence.
- **`scripts/test-eval-graders.sh`** (new, in CI) runs **all four** graders
  against an untouched fixture copy and requires a red for every eval id. That
  question — "can this assertion even fail?" — is the only reason the hollow
  `run` eval-2 grader was ever found, and it is now asked by the build instead
  of by luck. It also requires the pillar-1 graders **green on a synthesized
  ideal outcome**, so the mirror defect (a grader that can never pass) fails
  too, and covers the regressions that matter: a red step taken *after* the
  implementation is graded red, and a rationalized `VERDICT: PASS` on
  `tally-sneaky` is graded red.
- **Pillar 2's green side is deliberately not synthesized.** Writing a valid
  process contract in bash would reimplement the thing being graded; their green
  evidence is the committed benchmarks. The test prints that limit rather than
  letting the coverage look complete.
- **`scripts/check-fixture-leaks.sh`** (new, in CI) + **`scripts/fixture-leak-allow.txt`**:
  14 vocabulary patterns (`VERDICT:`, `baseline-sha`, `IMPL_SHA`, `RESULT=`,
  "the eval asserts", "pristine", "eval fixture", "is graded", …) over every file
  under `*/evals/fixtures/`. Both eval READMEs already carried this grep as a
  mandatory manual step; six leaks in one week is the evidence that a manual step
  is not a gate. Exemptions are per **path *and* pattern with a written reason**
  (6 entries, all `run-tests.sh` legitimately naming the `.check-log` it writes),
  a reason is required, an unknown pattern id fails loudly, stale entries fail,
  an empty scan exits 2 rather than passing vacuously, and
  `SKIP_FIXTURE_LEAKS=1` prints that it skipped.
- **The allowlist is proven load-bearing**: its test empties it and requires the
  real fixtures to *fail*. A vocabulary loose enough to let `run-tests.sh`
  through unaided would have let the `work` README leak through too.
- **Runbook** — README's "Skill evals" section and both `evals/README.md` files
  stop describing pillar 1 as hand-derived regexes and point at the graders and
  the two gates. `verify` executors are told to save `report.md` /
  `transcript.md` in the workdir root, where the grader looks.
- Built test-first per CLAUDE.md: both test scripts were written and seen red —
  graders absent, gate absent — before either implementation existed.

## Why no eval gate ran for this release

P22 phase 2 requires running a skill's eval before bumping when the diff changes
that skill's behavior. This diff touches no `skills/*/SKILL.md`, no agent and no
hook — only eval harness, tests, CI and docs — so there is no skill behavior to
regress. Stated here rather than left as an inference.

## Open, and stated rather than implied

- The gate scans file **contents**, so the fixture file *named* `baseline-sha` is
  still a standing hint sitting in the executor's workdir. Its contents are an
  opaque hash, and renaming it would change the `work` eval definition and
  invalidate the committed benchmark — so it is recorded in the allowlist header
  and in `skills/work/evals/README.md` instead of quietly accepted.
- **The measurement this unblocks has not been taken.** The `verify` iteration on
  the cleaned v0.36.0 fixtures is still unrun, so its bug-detection assertions
  still have no trustworthy result. That is the next step in the backlog's
  sequencing, and P26 existed to make it worth spending.
