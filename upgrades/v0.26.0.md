summary: Stops the harness from re-asking write permission for flywheel's own state. The loop's real approval gates are conversational — the spec sign-off and the plan approval — but the tool-permission layer knows nothing about them, so every save of a spec, plan, ledger entry, process contract or run report prompted again. A new allow-only PreToolUse hook pre-approves writes that resolve inside .claude/flywheel/ (symlinks resolved, traversal normalized); every other write keeps the normal permission flow. Marketplace installs pick it up on /plugin update + reload; vendored repos on re-vendor.
---

## What changed

- **New `scripts/write-allow.sh`**, wired as a `PreToolUse` hook on
  `Write|Edit|MultiEdit|NotebookEdit` (`hooks/hooks.json`): when the write's
  target resolves inside `<project>/.claude/flywheel/`, the hook emits
  `permissionDecision: allow`, so persisting the loop's own state (specs,
  plans, `LEARNINGS.md`, process contracts, `DATA.md`, run reports) no longer
  re-prompts after the owner already approved the spec and the plan.
- **Allow-only and fail-open by contract**: the hook never denies, never asks,
  and never blocks a write. Out-of-scope paths, malformed hook input, or a
  missing `python3` produce no output — the normal permission prompt appears
  exactly as before. Repo code, `.claude/settings.json`, and everything else
  outside the state dir are untouched by the grant.
- **Scope is checked strictly**: paths are resolved with `realpath` before the
  containment check, so a `..` traversal, a prefix sibling
  (`.claude/flywheel-evil/`), or a symlink planted inside the state dir that
  points elsewhere gets **no** grant. A bash pre-filter skips the python spawn
  for the out-of-scope majority of writes.
- **Vendored installs covered**: `install-vendored.sh` vendors the script into
  `.claude/flywheel/bin/` and merges the `PreToolUse` entry into the target's
  `settings.json`; `--uninstall` removes both.
- **Tests**: new `scripts/test-write-allow.sh` (allow inside, no grant for
  out-of-scope / traversal / sibling / symlink-escape paths, fail-open on bad
  input or missing python3), wired into CI; `test-install-vendored.sh` asserts
  the vendored hook is installed, merged once, runnable, and removed on
  uninstall.
- **Docs**: README gains a "State-write pre-approval hook" section explaining
  the two-layer permission model (conversational gates vs. harness tool
  permissions) and the hook's exact scope.
