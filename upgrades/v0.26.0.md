## What changed

- **`.claude/flywheel/PENDING-UPGRADES`** (new, state — never in the manifest):
  when `install-vendored.sh` refreshes a repo across versions, it records every
  upgrade note in the range `(old, new]` carrying `requires-action: true`, one
  version per line. Previously that warning lived only in the auto-update PR
  body — merging the PR without running `/flywheel:update` lost the pending
  strategies silently.
- **`scripts/session-start.sh`**: if the marker is non-empty, every session
  start prints a ⚠️ listing the pending versions and pointing at
  `/flywheel:update`. Pure local state — no network, independent of
  `FLYWHEEL_NO_UPDATE_CHECK`.
- **`skills/update/SKILL.md`** (§2.4): after executing and logging a version's
  strategy to `UPGRADES.md`, its line is removed from the marker; the file is
  deleted when empty.
- **Post-refresh smoke check**: the installer runs `bash -n` over every
  vendored hook script and aborts (non-zero, before the manifest/VERSION swap)
  on failure, so a refresh that would break the next session's hooks is never
  recorded as installed. The auto-update workflow inherits this: a broken
  refresh fails the job instead of opening a broken PR.
- **`--uninstall`** removes the marker; debt survives same-version re-installs
  unchanged (deduped, sorted).
- **Tests**: installer — pending recorded for the range (requires-action only),
  kept out of the manifest, survives re-install, removed on uninstall, broken
  hook aborts before VERSION; session-start — nag lists versions, silent on
  empty/absent marker.
- **Workflow PR body** now notes that the pending versions ride in the PR and
  will keep nagging until applied.

Spec: `.claude/flywheel/specs/p19-update-postprocess.md` (P19).
