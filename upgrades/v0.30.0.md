## What changed

- **Two-tier telemetry** (`work`, `loop`, `run`, `process`, `help`): each
  task/Rule transition now appends **one JSON line** to
  `.claude/flywheel/runs/<slug>/<date>.jsonl`; the HTML report at
  `…/<date>.html` is rendered from that JSONL **only at phase gates and at
  close** (and republished to the same stable artifact URL then). Previously
  the whole HTML page was regenerated at every transition — the single
  biggest output-token cost in the flow. Existing `.html` reports are
  untouched; new runs simply gain the `.jsonl` next to them.
- **Micro-cycle routing in `/flywheel:loop`**: before phase 1 it routes by
  size, stating the route chosen. A small task (~1 file / <~20 lines, no new
  entity/dependency/migration, obvious machine-checkable pass condition) runs
  a collapsed micro-cycle — mini-spec + metric in one message, **one**
  sign-off, then `work` → `verify`; review keeps its own diff routing. Gates
  are never routed away, only the documents. Scope growth mid-flight upgrades
  to the full cycle.
- **`gate.sh seal` + verify integration**: `/flywheel:verify` now runs the
  project's opt-in `.claude/flywheel/gate.sh` as its suite command when
  present, and after a PASS calls `gate.sh seal` (marketplace:
  `${CLAUDE_PLUGIN_ROOT}/scripts/gate.sh`; vendored:
  `.claude/flywheel/bin/gate.sh`) to record the passing tree signature — so
  the Stop hook cache-hits instead of re-running the same suite. Seal refuses
  an untrusted gate (a planted gate can't arrive pre-passed) and covers
  exactly one tree signature. Three new cases in `test-gate.sh`.
- **Skill descriptions trimmed**: all 17 frontmatter `description` fields
  rewritten terser (they are loaded into context every session), keeping the
  trigger vocabulary intact.
