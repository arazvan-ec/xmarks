## What changed

- **`scripts/install-vendored.sh`**: vendors `plan-route.sh` and `run-cost.sh`
  into `.claude/flywheel/bin/` alongside the hook scripts, plus
  `route-tiers.txt` (data, not executable) — `plan-route.sh` resolves its tier
  table beside itself, so the table has to travel with it. Uninstall already
  removes them: the manifest drives it, so no change was needed there.
- **`skills/plan/SKILL.md`**: the lint line now names all three paths —
  `${CLAUDE_PLUGIN_ROOT}` on a marketplace install, `.claude/flywheel/bin/` on a
  vendored one, repo-relative inside flywheel itself — and `allowed-tools`
  pre-approves each, so no form hits a permission prompt.
- **`skills/loop/SKILL.md`**: same treatment for `run-cost.sh`, which the cost
  block already pointed at repo-relatively (correct only inside this repo). It
  also now says what the command actually reports since v0.39.0: the per-route
  breakdown and the escalation rate, not just the two-run delta.

## Why it was broken

v0.39.0 shipped the route linter and the route-aware cost reader, but
`install-vendored.sh` copied only the five hook scripts. On the vendored install
— the one Claude Code web needs — neither analysis script existed. Both call
sites fail open by design, so the result was not an error but silence: a plan
whose riskiest step ran cheap would lint clean because the linter was never
found, and the evidence loop P27 depends on could not be closed at all.

`skills/verify/SKILL.md` already had the right convention (name the marketplace
path and the vendored path). The two newer call sites did not follow it.
