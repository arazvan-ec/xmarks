## What changed

- **`install-vendored.sh --agents-only`** — vendors `agents/*.md` into
  `.claude/agents/` and nothing else: no skills, no hook scripts, no
  `settings.json` rewiring. It is the only mode permitted to target the flywheel
  repo itself; the full self-install stays refused, because duplicating 17 skill
  bodies into `.claude/skills/flywheel-*` guarantees drift.
- **The narrowed run merges into `.claude/flywheel/.manifest` instead of
  replacing it.** The prune at the end of a full install is manifest-driven, so a
  narrowed manifest would have read as "this version dropped every skill" and
  deleted a consuming repo's whole vendored install. Covered by its own test.
- **`.claude/agents/*.md` committed** (six agents). Discovery happens at session
  start, so a copy generated by a session loses the race for that session — the
  files have to be present in the clone.
- **`scripts/check-agent-parity.sh`** — CI gate, both directions: a shipped agent
  nobody registered is a tier the dev loop loses silently; a registered agent
  nobody ships is a stale definition it would delegate to. The installer's
  `/flywheel:` rewrite counts as parity, and if the installer ever stops applying
  that rewrite the gate refuses to be trusted rather than mirroring a moved line.

Known-remaining: flywheel's **hooks** are still inactive in its own repo, so
`delegation-guard.sh` does not fire on flywheel-on-flywheel delegation.
