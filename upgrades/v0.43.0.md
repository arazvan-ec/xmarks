## What changed

- **`scripts/fixture-scratch.sh`** (new): instantiates an eval into a scratch
  workdir, optionally applies a committed reference solution, runs the suite and
  probes, grades with the suite's `check.sh`, and tears down. One `PASS:`/`FAIL:`
  line per step, exit 0 only if every requested step passed, exit 2 when it
  could not start — the graders' own contract. Replaces the ~40-line ad-hoc
  command every eval iteration used to retype, and the prose in the README
  runbook's steps 1 and 3.

  Addressed by `<skill> <eval-id>` rather than by fixture path, because a
  fixture does not identify an eval: `loop` evals 1 and 2 share
  `inventory-repo` and differ only in whether their `setup` runs `git init`
  (eval 2 deliberately does not, so that a *missing* `commit` field can be
  proven). The script reads `evals.json` and applies whichever schema the suite
  uses — a `files` list, or the eval's own `setup`.

- **Two latent defects fixed on the way.** The runbook said `W=$(mktemp -d)`
  while the `setup` commands are `cp -r <fixture> "$W"`, which nests the fixture
  into `$W/<fixture-name>/` when `$W` already exists — a workdir correct in
  every other respect that fails every grader. And nothing bound a reference
  solution to its fixture, which matters because
  `skills/work/evals/fixtures/cart-feature/cart.py` and `cart-bugfix/cart.py`
  are **byte-identical**: either solution's patch applies cleanly to the wrong
  fixture, so a clean apply proves nothing. A `MANIFEST` now declares the
  binding.

- **`skills/{verify,work,loop}/evals/solutions/`** (new, 7 solutions): the ideal
  outcomes `scripts/test-eval-graders.sh` grades, as committed assets rather
  than heredocs. `patch/` holds edits to files the fixture already has,
  `overlay/` holds files it does not, `apply.sh` holds ceremony and
  runtime-computed values, `steps/` holds patches `apply.sh` applies itself
  between commits, and `BASED-ON` pins the fixture tree's digest.

  Deliberately **outside `fixtures/`**: they are the answer key, and
  `check-fixture-leaks.sh` scans `*/evals/fixtures/**` only. That gate could not
  have policed this itself — `verify`'s overlay carries `VERDICT:` and `work`'s
  patches carry `RESULT=`, but `loop`'s ideal JSONL contains none of the
  vocabulary and would pass unseen — so "no `solutions/` inside any fixture" is
  its own assertion in the new test.

- **`scripts/test-eval-graders.sh`**: 403 → 241 lines, 13 heredocs → 1. The four
  synthesizers (`report_ideal`, `work_ideal`, `loop_ideal`, `honest_stop`) are
  gone; the arms that used them call the helper with the committed solutions, so
  the gate grades exactly what a person can reproduce by hand. **Every
  assertion is unchanged**, proved by the sorted set of 41 `  ok: ` lines being
  byte-identical before and after. Grading still does not go through the
  helper's `--check`: the helper exits non-zero when any step fails, so in the
  arm whose purpose is "the grader can fail", a broken helper would read as a
  passing red arm.

- **`scripts/test-fixture-scratch.sh`** (new, 45 assertions): the paired test.
  Runs against a synthetic eval tree via `FW_EVAL_ROOT` so every refusal path is
  reachable without planting anything in the committed suites, and against the
  real tree for the properties that are about the committed files. It exercises
  every solution by glob discovery rather than a hand-written list, so one added
  and never applied is impossible.

- **Docs**: the README runbook and the three `skills/*/evals/README.md` name the
  command instead of describing the ritual; `docs/research/improvement-proposals.md`
  gains P33, a deferred **P34** (a green arm for the `run` grader), and a dated
  decision-log entry.

- **Four defects found by review before merge, all in `fixture-scratch.sh`.**
  Folded into this version rather than a 0.43.1, since 0.43.0 has never been in
  `main`:
  - **Portability.** `sha256sum`, `sort -z`, `xargs -0r` and `find -printf` are
    GNU-only, so `--digest` and every `--solution` would fail on stock macOS.
    Now probed with the `shasum -a 256` fallback `scripts/gate.sh` already
    carries, and a plain `find | sort` walk. The test asserts the convention (it
    cannot run macOS), naming `gate.sh` as the pattern to match.
  - **`BASED-ON` ignored file modes.** Dropping `+x` from a fixture's
    `run-tests.sh` left every byte identical, so the digest still matched while
    an executor could no longer run the `./run-tests.sh` the eval requires. The
    executable bit — the only mode git records — is now part of the digest. All
    seven committed digests were regenerated, which is the mechanism working.
  - **`--suite` passed vacuously.** `process` and `run` fixtures carry no
    unittest suite, and `python3 -m unittest` exits **0** on "Ran 0 tests", so
    the helper reported a green suite having verified nothing. A zero-test run
    is now a failure that names the reason — the same refusal
    `check-fixture-leaks.sh` makes for zero scanned files.
  - **`--print-prompt` treated the workdir as sed syntax.** A path containing
    `&` emitted `…fw{{WORKDIR}}a` (in a replacement `&` is the whole match) and
    one containing `|` produced a sed error whose status was swallowed by the
    following `echo` — both exiting 0. Substitution is literal now, and its
    failure propagates.

## Not in this release

- **No green arm for `process` or `run`**, tracked as P34 and kept separate so a
  failure there is not ambiguous between "the format is wrong" and "the grader is
  wrong". `process` evals 1-2 are genuinely tautological — roughly 11 of 14
  assertions are `grep -Eq '^## Section'`, so an exemplary contract would assert
  only that a file written to match the greps matches the greps. **`process`
  eval 3 and all of `run` are not**, and P34 says why per eval rather than per
  skill: section-scoped `awk`, a regex carrying `${TODAY}`, and the
  `staged`/`not_unstaged` pair whose joint satisfiability nothing currently
  proves. Their green evidence remains a dated benchmark snapshot, which is
  evidence rather than a gate.

- **The eval suites were not re-run for this release, and did not need to be.**
  The diff touches no `skills/*/SKILL.md`, no agent and no hook, so there is no
  skill behaviour to regress and the P22 phase-2 pre-bump eval gate does not
  apply. Stated here rather than left as an inference from a silent release.

- **`fixture-scratch.sh` is not vendored.** `install-vendored.sh` vendors the
  scripts the skills invoke in a consuming repo (`plan-route.sh`,
  `run-cost.sh`); this one resolves `skills/*/evals/**`, which a consuming repo
  does not have, so a vendored copy could only fail confusingly. Same class as
  the `check-*` and `test-*` scripts, none of which are vendored.
