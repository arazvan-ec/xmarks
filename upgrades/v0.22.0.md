## What changed

- **`/flywheel:process`** (`skills/process/SKILL.md`) — new opt-in section
  "Multi-runtime profiles": when the owner wants the same operation executed by
  more than one AI runtime with comparable outputs (or by agents without this
  plugin), the contract declares a `profile` input (default `claude`),
  namespaces every persisted output per profile, makes the idempotency key
  composite `(profile, key)`, adds a profile-isolation guardrail (own namespace
  only; shared hubs/registries preserve every profile's entries), phrases
  capabilities not every runtime has (artifact URLs, host-task ledgers) as
  runtime-dependent with fallbacks, and creates/refreshes a root `AGENTS.md`
  runbook with ground rules plus a copy-paste task prompt for external agents.
  The owner's verdict on which profile wins feeds the Improvement log, so every
  profile inherits the learning. Existing "Maturing" section renumbered 4 → 5.
- **`/flywheel:run`** (`skills/run/SKILL.md`) — parses a `profile=<id>` token
  when the contract declares profiles (ignored otherwise), suffixes the
  telemetry report `<date>-<profile>.html`, and executes as that profile:
  writes only inside its namespace, treats sibling profiles' outputs as
  read-only context, preserves their entries on shared surfaces.

Pattern proven first in the wild: the `keep-experiences` contract v2 in the
owner's `keep` repo (Claude vs. Manus portfolios competing over the same
imported dataset).
