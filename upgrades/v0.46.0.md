## What changed

- **`scripts/git-tracking-refs.sh`** (new): a `SessionStart` hook. On a clone
  that is **both shallow and single-branch** — the signature of the
  `git clone --depth 1` an agent session arrives with — it replaces

  ```
  +refs/heads/main:refs/remotes/origin/main
  ```

  with the wildcard refspec a plain `git clone` would have written. It fetches
  nothing and touches nothing else.

- Registered on both delivery paths: `hooks/hooks.json` for installed plugins
  and `install-vendored.sh` for vendored repos, with
  `test-install-vendored.sh` asserting the second. That pairing is the lesson
  of 0.44.0/0.44.1, where the first was updated and the second was not.

## The defect

Push a **new** branch from a single-branch clone and git stores
`branch.<n>.remote` and `branch.<n>.merge` but creates no
`refs/remotes/origin/<n>`: the narrow refspec maps nothing to it. `@{u}` then
fails to resolve, and every tool that reads it concludes the branch was never
pushed.

It is a lie with a convincing shape — the commits **are** on the remote, the PR
opens fine — so the natural reaction is to push again, or to go looking for a
problem that does not exist. It showed up three times on 2026-09-13, once in a
session that diagnosed it independently, each costing minutes and producing a
false "N unpushed commits" warning at exactly the moment a job reports done.

Widening the refspec before the push is what makes `git push` create the
tracking ref, so the fix is prospective: it repairs the next push, not the last
one.

## Scope and safety

This is the first flywheel hook that **mutates** anything: one line of the
repo's local git config. It never touches the working tree, history, a ref's
content or the remote, the value it writes is the git default, and it is
reversible with one `git config --replace-all`.

Three guards keep it off repos that are none of its business, each one silent:

- **Not shallow** → untouched. A deliberate `--single-branch` full clone is a
  choice about fetch cost, not an accident.
- **More than one fetch refspec** → untouched. Someone configured that remote on
  purpose.
- **Already the wildcard form** → untouched, which is what makes it idempotent.

`FLYWHEEL_NO_REFSPEC_FIX=1` disables it outright. No git, no repo, no `origin`
or any error at all and it prints nothing and exits 0: a session must never fail
to start because of this.

## Action required

None beyond re-vendoring (`/flywheel:update`). The hook is silent on any clone
it does not apply to, and on a clone it does apply to it prints one line saying
what it changed and why.
