## What changed

The same tree now gets the same verdict. Three places depended on something
else. Findings 3–5 of `docs/research/review-v0.63-v0.71.md`.

### read-meter's fixture no longer races the clock

The exclusive-cut arm of `scripts/test-read-meter.sh` assumed two fed calls land
in the same wall-clock second. When the second ticked between them, the arm
failed, and that turned `main` red after #91. The fixture now stamps both rows
with the first row's `ts`. The meter is unchanged.

### A tied merge in route-honored gets one verdict

`check-route-honored.sh` picked a merged transition's planned task with `max()`
over a set. When two tasks tied on tier (`opus/high` and `opus/high+delegate`),
`PYTHONHASHSEED` picked the winner, so one tree exited 0 or 1 from run to run.
The choice now runs over plan order, and a tie goes to the non-delegated task.
The delegated task is reported as absorbed, a notice like every merge.

### Cutoffs compare instants, not strings

`"…20:00:00.5Z" >= "…20:00:00Z"` is false as text, and a non-`Z` offset sorts by
its local wall time. So a post-cutoff line could read as pre-cutoff, and a
fatal finding could drop to a notice. `fw_cutoffs.py` gains `instant()` and
`binds()`, and all three cutoff gates compare through them:

- `check-telemetry.sh` — the phase rule;
- `check-route-honored.sh` — per line and per run;
- `check-task-closure.sh` — the plan's author date.

How `binds()` treats edge cases:

- An empty `ts` still does not bind.
- A present but unplaceable `ts` binds. A malformed timestamp cannot buy the
  corpus's forgiveness.
- A cutoff override that is not an instant makes the gate exit 2.

Nothing in the existing corpus changes class: every line in it is whole-second
`Z` or `+00:00`, and those order the same both ways.
