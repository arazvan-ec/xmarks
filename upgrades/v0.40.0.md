## What changed

- **`skills/work/SKILL.md`**: step 5 is now **Commit** (advance moved to 6). A
  green check means one finished logical change, so it lands as
  `git commit -m "<subject>" -- <the task's paths>` followed by
  `git push -u origin <branch>`. The pathspec form is the point: it commits that
  task only and leaves the index alone, where a bare `git commit` would absorb
  whatever `spec`/`compound` had staged, and `git add -A`/`-u` would sweep in
  work that was dirty before the cycle started. History rewriting (amend,
  rebase, squash, force) is explicitly not the loop's to do. The telemetry line
  gained `"commit": "<sha>"`, and the anti-rationalization table gained
  "I'll commit it all at the end."
- **`skills/debug/SKILL.md`**: a step 7 committing the fix and its regression
  test as one change, under work's rules.
- **`skills/ship/SKILL.md`**: steps 1–2 rewritten — review the per-task history
  the branch already carries and never squash/rebase/amend it; commit only the
  remainder (ledger, spec, docs), with "nothing left to commit" named as a
  normal outcome rather than an error.
- **`skills/loop/SKILL.md`**: the cycle rules state the invariant, so the outer
  loop no longer reads as if commits wait for `ship`.
- Docs: README feature paragraph, `/flywheel:help` good-to-know bullet.

## Why no action is required

The prescribed commands are exactly the ones `scripts/bash-allow.sh` has
pre-approved since v0.28.0 (P21): a plain `git commit`, and a force-free
`git push [-u] origin <current-non-default-branch>`. No hook, script or
permission surface changed, so an installed repo gets the new behavior by
re-vendoring the skills and nothing else.

Committing fails open by design — not a git repo (the eval fixtures aren't),
no remote, nothing to commit, or a rejected push is reported once and the inner
loop continues. On the default branch the loop creates a feature branch before
the first commit (that one prompts) and, if declined, skips committing rather
than writing to `main`.
