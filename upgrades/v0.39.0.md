## What changed

- **`skills/plan/SKILL.md`**: the task block is now **pinned** —
  `### T<n> — <title>` plus `route:`, `risk: highest` (exactly one task),
  `changes:`, `check:`, `test-first:` — and a 3-tier rubric says where a task
  belongs: **T1** `haiku/low+delegate` for fully-specified mechanical work,
  **T2** `sonnet/medium` for ordinary test-first implementation, **T3**
  `opus/high` for judgment and always for the riskiest step. The plan opens
  with a routing table, and the gate makes explicit that approving the plan
  approves its routes — including any model switch `work` will ask for.
- **`skills/work/SKILL.md`**: honors the route (delegate to `executor`, switch
  or ask once for a higher tier, and *report* a route it could not honor rather
  than silently downgrading), **escalates one tier after a second red on the
  same check** instead of grinding at the cheap tier, and records `route` plus
  `route_escalated_from` on the telemetry transition line. A mis-route that cost
  real time is a `decision` learning at compound time — evidence-gated as usual.
- **`agents/executor.md`** (new): the T1 vehicle. Haiku, `effort: low`, one
  fully-specified task in its own context, and a required last line of
  `DONE: <check>` or `ESCALATE: <the decision this task actually needs>`. The
  cheap tier is allowed to decline a judgment call; it is not allowed to guess.
- **`agents/{verifier,evaluator,reviewer-*}.md`**: each pins `effort:` next to
  its `model:` — `low` for the mechanical run-and-report roles, `high` for the
  adversarial reviewers. This extends v0.9.0's model routing to the second knob.
- **`scripts/plan-route.sh`** + **`scripts/test-plan-route.sh`** (new pair,
  test-first): validates one legal `<model>/<effort>[+delegate]` and one check
  per task, exactly one `risk: highest`, and **fails a plan whose riskiest step
  runs on the cheapest tier** (haiku or low effort). Prints the tier summary the
  plan gate shows. Exit 0 OK · 1 lint failures · 2 unusable input.
- **CI**: runs the new test, plus `scripts/test-run-cost.sh`, which shipped with
  P23 but had never been wired into the workflow.
- **Docs**: README agent list + a stage-routing section; `/flywheel:help` map.

## Evidence and its limits

`effort:` in agent frontmatter is a real Claude Code knob, not an assumption:
the shipped CLI (2.1.267) carries `effort: union(enum(low|medium|high|max),
int).optional()` in its agent-file schema and rejects a bad value with
`Agent file … has invalid effort …`. `claude plugin validate . --strict` passes
with the field present, but it validates manifests — it does not prove the
loader consumes it, and a headless `--debug` probe surfaced no diagnostic
either way. Since the field is optional, a CLI that ignores it simply routes by
`model:` plus session effort.

The payoff is **not** claimed in token counts anywhere: the linter counts tasks
and tiers, and any cost delta is read off the existing `cost` proxies
(`bytes_out`/`tool_calls`/`elapsed_s`) via `scripts/run-cost.sh` (P18/P23).
Whether the rubric's tiers are the *right* tiers is still unmeasured — the
`route_escalated_from` field exists so the next cycles produce that evidence
instead of an opinion.
