## What changed

### A shipped cycle says what it learned (P69)

A new `Stop` hook, `compound-due.sh`, blocks the turn when a run this branch
touches has a `phase: ship` line and no `phase: compound` line. Run
`/flywheel:compound`, which now appends that line with `entries: N`. If the
cycle proved nothing durable, append the line yourself with `entries: 0` and a
`reason`. Runs that no commit on your branch touched never block. Before this,
14 of 16 shipped runs in flywheel's own repo recorded no compound outcome.

`check-hook-parity.sh` now compares hooks whose command takes an argument. It
used to skip `toolbar.sh stop` and `toolbar.sh remind` entirely.

### A lesson about flywheel reaches flywheel (P70)

When `/flywheel:compound` writes an entry about flywheel itself (a skill, hook,
script, gate, the installer, a format), it offers `upstream-issue.sh`. The
script renders the entry as a prefilled **flywheel feedback** issue URL on the
plugin's repo. It keeps only flywheel paths, marks missing evidence as
`unverified`, and sends nothing: you review the form and submit it. Reread the
prose for anything private first, because the plugin's repo is public.

### Hooks no longer read old history as current work (P71)

On a checkout with no ref besides the current branch and its upstream (a
repo with only `main`, say), `compound-due.sh` and `toolbar.sh` compared the
branch against nothing and treated every old run or plan as this branch's.
Both now count only uncommitted files in that case.

Vendored installs get both scripts in `.claude/flywheel/bin/` and the new Stop
hook in `.claude/settings.json` on the next refresh.
