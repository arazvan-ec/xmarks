## What changed

- **`install-vendored.sh --hooks-only`** — writes the eight hook registrations
  into this repo's `.claude/settings.json` and nothing else: no skills, no
  agents, no `bin/` copies. It is **self-target only**; a consuming repo is wired
  by the full install, and a narrowed run there would point registrations at
  files nobody copied.
- **The registrations point at `$CLAUDE_PROJECT_DIR/scripts/<name>.sh`**, not at
  `.claude/flywheel/bin/`. The scripts are already in this repo, so copying them
  would recreate P41's duplication and need a parity gate of its own.
- **`check-hook-parity.sh` gained its third direction.** It already proved
  `hooks.json` and the installer agree, and that every registered script lands in
  `bin/`. It now also proves flywheel's own settings register what flywheel
  ships — the assertion whose absence let eight hooks sit unregistered for nine
  versions without a trace.
- The full install is unchanged: its existing tests stay green, unedited, and a
  foreign target still receives vendored `bin/` copies.

Checked before wiring, because activating hooks changes every session in this
repo rather than one: the `Stop` gate is **inert** (opt-in on a project
`.claude/flywheel/gate.sh`, which does not exist here), `delegation-record.sh`
writes to the system temp dir rather than the project, `write-allow.sh` and
`bash-allow.sh` only *remove* permission prompts, and `read-prime.sh` is
advisory. The one behavioral change is `delegation-guard.sh`, which will now
`ask` before an `Agent`/`Task` call — its purpose, and the thing it failed to do
for every delegation in the P40a–P42 cycles.

**Unproven at release time:** hook registrations, like agent definitions, are not
picked up by the session that writes them. The acceptance observation — the
guard actually firing — belongs to a later session, and is recorded in the spec
rather than assumed here.
