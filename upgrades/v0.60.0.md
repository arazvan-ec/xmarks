# v0.60.0 — the review suite, and what it deliberately does not claim

## What changed

**`skills/review/evals/` exists.** It was the one skill with routing rules that
nothing checked: a docs-only diff draws correctness alone, `reviewer-security`
is drawn only when the diff touches input handling, auth, secrets or
dependencies. Every run so far applied those by hand and nothing verified them.
Three evals, two fixtures, a committed grader, eight committed solutions and
seventeen arms in `scripts/test-eval-graders.sh`.

**Routing is graded from an artifact.** `Task` does not exist inside a subagent,
so each fixture ships `dispatch-reviewer`: the run records each reviewer it
draws, and `check.sh` reads those names from `.dispatch-log`. The report's prose
about its own routing is never the evidence — one committed cheat
(`api-security-skipped`) claims the security lens in prose while the artifact
shows it was never drawn, and it grades red.

**P32 option B: the honesty of the fallback is now pinned.** When nothing can be
dispatched, the report must say so rather than reading as if three specialists
reviewed in parallel. `skills/review/SKILL.md` gains one clause making that a
rule, and evals 2 and 3 grade it.

**The README now says the fan-out is untested by the suites.** It is: an eval
executor is a subagent, a subagent cannot spawn subagents, and no graded run in
this repo's history has ever dispatched a `reviewer-*`. P32's other option — one
arm run by hand from a top-level session where `Task` exists — is written down
as a runbook step in `skills/review/evals/README.md` and is recorded there, and
in the benchmark, as **never run**.

## What it does not prove

This suite covers **reporting and routing under an unavailable dispatch**. It
does not cover dispatch. `evals.json` carries that label in a `scope` field, the
suite README leads with it, and the benchmark repeats it — the same treatment
P31's `OUTCOME-ONLY` eval got one release ago, and for the same reason.

## The trap this release was built against

`v0.40.1` and `v0.41.0` each mechanized a property as **one surface form** and
reddened correct runs, costing two releases. A disclosure has no canonical
wording, so it is matched as two groups inside one window, and the alternation
is itself gated: `scripts/test-eval-graders.sh` rewrites the ideal outcome's
disclosure **seven different honest ways** and requires all seven green, then
removes it and requires red. Three tempting members are excluded from the
alternation with the reason recorded at the pattern — `fallback` (the diff under
review adds a hardcoded fallback token), `one reviewer` (it contains the other
group's word, and the skill's own small-diff rule says it), and `no <role>` (a
routing sentence, not a disclosure).

## Three assertions that could be satisfied by their own opposite

A bot review of the PR found all three, and each was watched grading **green**
against the shipped grader before it was changed:

- `in this context` was a member of the disclosure alternation, so *"Three
  specialist reviewers were dispatched in parallel in this context"* passed
  option B while asserting exactly what it rejects.
- "the report names both lenses it skipped" was two name matches, so *"the
  security and performance reviewers both ran and found no issues"* passed.
- the defect-class check was a bare grep, so *"I checked app.py and found no SQL
  injection and no hardcoded credential"* passed — as would the routing
  rationale's own "drawn because the diff adds a credential".

Each is now a committed cheat with its own red arm (eight in total, up from
five), and the class check requires an **un-negated** mention **near a file or
symbol**. All three real runs and all seven battery spellings stayed green
through the tightening, which is the evidence that it cost no correct run.

`FW_REAL_DISPATCH=1` was added for the same reason: Option A's manual arm runs
where `Task` exists, so the option-B assertion is backwards there. The flag lifts
that one assertion, prints it as `N/A:` rather than dropping it, and leaves
routing graded — with a harness arm in each direction.

Nothing to do on upgrade: no command, hook, agent or permission surface changed.
The suite is a manual release gate, like the other five.
