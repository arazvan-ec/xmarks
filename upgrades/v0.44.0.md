## What changed

- **`scripts/check-invocation-budget.sh` + `scripts/invocation-budget.txt`**
  (new, wired into `validate-plugins.yml`): fails when any `skills/*/SKILL.md`
  exceeds the committed ceiling, printing the per-skill breakdown largest-first
  so the diff says *which* body grew. Same shape as P24's description budget —
  policy in its own file, a logged `SKIP_INVOCATION_BUDGET=1` escape, malformed
  input failing loudly rather than counting as zero.

  **Per-skill, not a total**, which is the whole difference from P24. Every
  session pays every `description`, so their invariant is a sum. A session pays
  the *body* of the skills it actually invokes, so a sum would measure a cost
  nobody pays and would let the largest skill grow as long as a small one shrank.

  Measured in bytes (`wc -c`), not characters: `wc -m` is locale-dependent —
  under `LC_ALL=C` it silently equals `wc -c` — and a gate whose verdict changes
  with the runner's locale is not a gate.

- **`skills/<name>/references/<topic>.md`** as the progressive-disclosure
  convention, documented in `CLAUDE.md`. The body holds the procedure and the
  rules that bite; detail a single step consults — templates, format
  catalogues, rationale, onboarding material — moves to a reference **cited by
  path from the step that needs it**, so it enters context only when that step
  is reached. The same gate fails a citation that does not resolve: a body
  pointing at a file nobody wrote is worse than the prose it replaced, because
  the model proceeds silently without the rule.

- **Six bodies extracted**, one commit each, each proving by diff that no removed
  line vanished: `help` 8,395 → 4,342 (the fourteen "good to know" bullets),
  `process` 8,280 → 4,458 (the 54-line contract template), `run` 5,703 → 4,498
  (the progress-ledger mechanics), `update` 5,363 → 4,341 (the upgrade-strategy
  procedure), `compound` 4,716 → 4,231 (the `fixture` contract), `work` 8,385 →
  5,259 (the transition line's shape, the routing cases, the delegation
  thresholds). **No rule was moved out of a body** — where a rule's rationale
  moved, the rule itself stayed, in several cases stated more strictly than
  before.

- **`install-vendored.sh` vendors `references/`** with the body it belongs to,
  through the same rewrite and the same manifest, so pruning needs no special
  case. Uninstall does: it `rm -rf`s a vendored skill dir only when the manifest
  says we wrote its `SKILL.md`, and in the branch that restores a user's own
  `SKILL.md` the dir is theirs and is kept — so our `references/` is removed
  explicitly there, or it would sit orphaned beside a body that never cites it.

## Why now

Over the five days spanning v0.39.0–v0.43.0 the **governed** cost held —
descriptions 3,301 → 3,326 against a 3,600 budget — while the **ungoverned** one
grew 14%: bodies 60,527 → 69,065 B, `work` +74%, `plan` +247%. Every one of those
diffs shipped through a spec and a review. Nobody did anything wrong; there was
simply no number that would have said so.

## The ceiling is 5,300, and that is a compromise

P35 was signed at 4,500 B. Five of the six skills in scope reached it with room
to spare. `work` did not: after everything reference-shaped had moved, 759 B
remained that was nothing but rules — the five-step inner loop, the commit rules,
the route contract, the standing rule, and the anti-rationalization table, which
is the guardrail against the exact failure the skill exists to prevent. Moving
it to buy bytes would have been the silent weakening the spec's Safeguards name.

The ceiling was raised globally to 5,300 rather than carrying a per-skill
exception. The cost, stated rather than glossed: the other sixteen skills now
hold between 800 and 4,000 B of slack the ratchet no longer reports, so the drift
this release exists to stop remains possible inside that slack. Per-skill
exceptions, or splitting `work`, stay available as a follow-up.

## Not in this release

- **No chain-level budget.** `/flywheel:loop` pays six bodies in sequence — still
  the largest single context cost in the plugin. Deliberately left to its own
  proposal, once the per-skill ceiling has held for a few releases.

- **Symlink hardening in the vendor loop**, left open by review at Low severity:
  a `references/` entry that is a symlink in the source checkout would be read
  through and vendored. It needs commit access to xmarks to plant, and the same
  gap already applies to every other file the installer vendors, so it is
  tracked as a follow-up rather than half-fixed here. See the P35 section of
  `docs/research/improvement-proposals.md`.
