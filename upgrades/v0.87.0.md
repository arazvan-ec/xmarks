## What changed

### The sweep stops re-running itself (P75)

`check-task-closure.sh` executed a plan task's `check:` once per task, and in
this repo 127 tasks cite 48 distinct commands. It now runs each distinct check
once per gate run and reports the result on every task that cites it, red ones
included. On this repo that took the gate from 556 s to 228 s, with identical
verdicts row by row.

`sweep.sh` gives its check-task-closure step `FW_SWEEP_ACTIVE=1`. A plan task
that cites `bash scripts/sweep.sh` (P59, P60) would otherwise start a whole
second sweep from inside the first. With the marker set, that nested sweep says
`SKIPPED nested sweep` and exits 0, and the enclosing sweep, which is running
every step anyway, gives the verdict. This mirrors the existing
`FW_TASK_CLOSURE_ACTIVE` skip.

Nothing to do in a repo that uses flywheel.
