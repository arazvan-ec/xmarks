## What changed

- **`skills/verify/evals/benchmarks/2026-07-30/`** (new) — `benchmark.json` +
  `benchmark.md`. **With-skill 11/11 assertions across the 3 evals (1.00),
  baseline 8/11 (0.71), delta +0.29.** First iteration against the clean
  (v0.36.0) fixtures, and the first graded by a committed grader
  (`check.sh`, v0.37.0) rather than regexes re-derived by hand. This supersedes
  `benchmarks/2026-07-29/` as the regression baseline.
- **The delta is one assertion, three times over.** Every baseline run failed
  *exactly* the machine-parseable `VERDICT:` last line and passed everything
  else. Last lines: `finished.` / `Do not ship on the strength of the unit
  tests…` / `…something CI enforces on every change.` — all correct advice, none
  parseable by a gate.
- **The claim is now narrower and better supported.** The baseline is not weak at
  verifying: it found `rows[:-1]` and the dropped 5.25 row, found the `n -= 1`
  double header subtraction, explained *unprompted* why a green unit suite
  carries no information about a metric written in terms of CLI stdout, and ran
  5-mutant mutation testing on the clean control. What `verify` demonstrably
  supplies is the **contract** — a verdict a gate can read without a human. The
  README's baseline-arm section says exactly that, so the number is not cited as
  something it does not show.
- **`benchmarks/2026-07-29/COMPROMISED.md` updated**: both of its predictions
  held. The delta survived removing the answer key (**+3/11 clean vs +3/10
  leaked**), and the assertions it flagged as non-surviving — bug detection,
  evidence citation, ran-the-real-CLI — **still** pass in both arms with the leak
  gone. They are regression guards, not skill value; that is now measured rather
  than withheld.
- **`benchmarks/2026-07-30/VOID-attempt-1.md`** (new) — a first attempt was
  voided **before grading**. The subagent harness refuses `Write` on files it
  classifies as reports, and whether an executor routed around it with a shell
  heredoc **correlated perfectly with the arm** (two with-skill runs did, all
  three baselines declined). Grading that would have measured "did the executor
  work around a tool block" and reported it as verification discipline — the same
  confound family as the fixture leaks, pointing the same flattering direction.
  Salvaging the two gradeable with-skill runs was rejected as survivor-biased.
- **P26 paid for itself on first use.** The grader's refuse-on-absent-artifact
  rule is what surfaced the confound: a grader that treated absence as silence
  would have produced a tidy 2/3-vs-0/3 sweep and the delta would have shipped as
  skill value. That is the exact failure mode "a grader that passes on absence is
  worse than no grader, because it reads as evidence" was written against.
- **Runbook fix (README)** — the `verify` executor brief must name the write
  mechanism (Bash heredoc, verify non-empty before finishing), stated
  **identically in both arms** since it is plumbing and hints at nothing. The
  general rule is stated too: any assertion that reads an artifact needs the brief
  to guarantee the artifact can exist, or an unproduced artifact is
  indistinguishable from a skill failure.

## Honest limits of these numbers

- **1 run per arm.** No within-arm variance; the pass-rate stddevs in
  `benchmark.json` are across evals, not across repeats.
- **`time_seconds` is not latency.** All six executors ran concurrently, so
  wall-clock is contended. `tokens` and `tool_calls` are exact per-subagent
  accounting: with-skill mean 47.1k vs baseline 43.9k, so the skill costs ~3.3k
  more per run for the contract it adds.
- **Assertion units changed.** The grader emits 11 lines (3+5+3) mechanizing
  `evals.json`'s 9 committed expectations (3+4+2); 2026-07-29 hand-split the same
  expectations into 10. Compare **pass rates** across iterations, never raw
  counts. `evals.json` itself is unchanged.
