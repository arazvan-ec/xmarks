## What changed

- **`skills/loop/evals/`** (new): fixture `inventory-repo`, two evals, a
  committed `check.sh`, and a README holding the ground truth. Eval 1 runs the
  cycle in a git repo; eval 2 runs it where committing is impossible, because
  the absence of a field cannot be proven by a passing run.
- **`skills/work/SKILL.md`**: Commit discipline gains **"No commit, no field"** —
  when the cycle is not committing, `commit` is *omitted* from the transition
  line, never a placeholder and never prose explaining the absence. Same rule the
  `cost` object already had.
- **`scripts/test-eval-graders.sh`**: `loop` joins the red-on-untouched sweep and
  gets a green-on-ideal, plus three cases of its own — a fabricated sha and a
  swept commit must grade red, and a commit holding only `.claude/flywheel/`
  paths must not count as a sweep.
- Docs: README "Skill evals", `docs/research/improvement-proposals.md` (P29).

## Why the eval had to exist

`work` writes its JSONL only inside a `/flywheel:loop` cycle, and every other
suite runs a skill standalone — so the telemetry was written by one skill and
read by no test. The `commit` field made that urgent: it is the only value a
flywheel skill records about something outside its own files, and parsing it
proves only that it is 40 hex characters, which a fabricated sha also is.
`git cat-file` is the difference between a parsed claim and a verified one.

## What the first run found

Both defects are in the benchmark at `skills/loop/evals/benchmarks/2026-09-09/`:

1. **The skill's.** In a non-git workdir the executor wrote
   `"commit": "none (not a git repo; commits skipped for cycle)"`. Honest, but
   prose in a parsed field — and the contract was silent about absence. Hence the
   "No commit, no field" rule above, verified green on a re-run.
2. **The grader's.** It failed a run that swept nothing, because the cycle's own
   `.claude/flywheel/bin/render-run.py` ends in `.py` and lives under `.claude/`,
   matching both sides of the sweep test. Source now means `.py` outside
   `.claude/`.

## Nothing to do on update

The eval suite is release-gate machinery for this repo; installed repos just
re-vendor. The one behavioural line — omit `commit` rather than filling it —
changes what a transition line looks like when a cycle cannot commit, and no
consumer breaks on an absent optional field.
