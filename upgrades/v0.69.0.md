## What changed

Three P2 findings from review against v0.65.0 and v0.66.0. Each was **reproduced
on a fixture before anything was changed**, and all three held.

### The delegation suffix now participates in the comparison

`check-route-honored.sh` ranked a recorded route by model and effort and
discarded the `+delegate` suffix. So a plan that bought `haiku/low+delegate`
against a record that said `haiku/low` compared as **honored** — the gate
reported success for a subagent that never ran, which is the one thing the tier
alone cannot show, and the thing P41 and P49 exist to track.

Tier and delegation are different axes, so the suffix is read and compared
separately. A **missing** delegation the plan bought is fatal from the same
cutoff as every other unrecorded deviation. **Extra** delegation the plan did not
ask for is a notice: less was spent, not more.

### A plan with no record is named

Discovery started from subdirectories of `runs/`, so a plan whose slug had no run
directory was never reached — the gate exited 0 having said nothing about it.
Twelve plans in this repo were in that state: seven with no directory at all, and
five whose directory holds only an HTML report and no JSONL. (A count taken by
hand said seven; the gate found the other five.)

They are **named and counted, never failed**. `check-telemetry.sh` already owns
the duty of failing a spec with no telemetry, and these are exactly the cycles
its baseline exempts *with a reason* — failing here too would contradict a
decision already taken. Saying nothing was the defect.

### The meter's explicit cut is exclusive

`read-meter.sh --since <ts>` filtered with `>=`. The documented call passes the
**previous transition's** timestamp, and that transition already counted every
call bearing it — rows are second-granular, so those calls were handed to the
next transition as well. For `bytes_in` that was a small double-count. For
`max_read` (v0.66.0) it is a maximum the transition never made: on the fixture,
a cut at the boundary second reported `max_read=50000` from the previous
transition's call.

An explicit `--since` is now **exclusive**. `--since first` stays inclusive: it
names a row rather than a boundary, and excluding it would drop the one call a
cycle's first transition exists to measure. One boolean decides, set where
`since` is resolved, so the two cuts cannot drift.

Nothing to do on upgrade. Passing the previous transition's `ts` is now exactly
right rather than approximately right, and `skills/work/references/work-detail.md`
says so.
