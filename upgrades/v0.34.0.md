## What changed

- **`skills/process/SKILL.md` §5 pins the Improvement-log entry format** —
  `### <YYYY-MM-DD> — <one-line what changed>` followed by the why, identical to
  `run` §4, so a contract's log reads the same whether a revision or a run
  matured it. `skills/process/evals/check.sh` requires that heading again;
  v0.32.0 had loosened it to accept any dated line and flagged fixing the skill
  as the follow-up. **This is that fix, verified**: the eval-3 executor emitted
  the heading unprompted and the strict assertion passed.
- **`work`'s eval katas no longer hint the method.** Both prompts named
  `./run-tests.sh` and forbade `python3 -m unittest`, which told the executor
  tests were the medium before the skill said anything — the v0.31.0 iteration's
  own notes give that as why both arms tied at 8/8. The prompts are now a plain
  feature request and bug report; the runner requirement moved into the fixture
  (`test_cart.py` refuses to import without `KATA_HARNESS=1`, which only
  `run-tests.sh` sets), so `.check-log` still exists for grading whichever arm
  runs. The old benchmark is marked `SUPERSEDED.md`, not deleted.
- **Grader bug fixed in `skills/run/evals/check.sh` (eval 2).** All three of its
  assertions were satisfied by the seed fixture, so **a run that did nothing
  scored 3/3** — the idempotency gate could not fail. It now requires the row's
  `audited` field to carry the run date and the datastore to be **staged**
  (which DATA.md demands), both false on an untouched fixture. Verified red on
  the untouched fixture, green on a correct simulated upsert, and red again on a
  duplicated row.
- **README — the baseline arm** is now a documented procedure with its cost and
  an explicit *not run* status, so pillar 2's green assertions are never cited as
  evidence the skills beat an unaided model.
- **Evidence**: `skills/process/evals/benchmarks/2026-07-30/benchmark.json`
  (3/3 evals, 39/39 assertions, ~133k subagent tokens, no grader changes needed).
- **Spec**: `.claude/flywheel/specs/p25-eval-gaps.md`.

## What is still not known

The `work` kata rewrite is *designed* to discriminate; **whether it does is
unverified** — no iteration has run against the new prompts, and the arms may
still tie. If they do, the honest outcome is to say so in the README rather than
let 100% read as skill value.
