# Answering review findings on a PR

Use when a reviewer (a person, Codex, `/code-review --comment`) leaves findings
on a PR this session owns. Done by hand from memory on PR #95 (P58); the order
matters, because each step is what makes the next one checkable.

1. **Read the whole PR on its head**: every unresolved thread, CI on the latest
   commit, mergeability. An event that echoes your own reply is not a request.
2. **Per finding, reproduce first.** Write the arm that shows it red, or state
   exactly why it does not reproduce. A fix without a red arm is a fix for a
   bug nobody has seen.
3. **Fix all of them in one change**, run the paired tests and the full sweep,
   and commit. Do not push yet.
4. **Reply on each thread before the push.** Name the commit, say it is being
   pushed, say what changed and which arm proves it. Where you are not fixing
   one, say why: already fixed, does not reproduce, or out of this PR's scope.
   Optional nits get one line: taken in this push, or left as is and why.
5. **Push**, then **resolve** the threads you fixed. Leave unresolved any
   thread you answered with a disagreement, so the reviewer decides.
6. **Release notes**: when the fix changes shipped behaviour, add a line to
   the note of the version that carries it, naming the reviewer.
7. **Telemetry**: one `phase: review` transition line naming how many findings
   were reproduced and fixed.
